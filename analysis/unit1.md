There is one primary key in each table to represent the rows of data that could be displayed in the foreign keys of other tables. The Passengers table has a primary key of passenger_id, which records each passenger's index. When an ON DELETE command is used on this table against the index, the entire row will be deleted. In this scenario, all of the passenger information will be removed when requested. The information in the Passengers table will be used in other rows such as the Bookings table. To prevent the parent row from being deleted while it is being referenced in other rows, a RESTRICT rule would be enforced for this relation. 


The Flights table holds the flight_id primary key that would be used to identify rows in this table that will be used to reference the information of a flight. This value is connected to a variable in the Bookings table as a foreign key to keep a record of the available flights and who is assigned to them. The Bookings table has a primary key of booking_id in the event that someone wants to look up a booking by index. The ON DELETE rule would apply here too, but its only foreign key is booking; using CASCADE could be a better fit.


The Airports table has two primary keys for the index of each airport and their abbreviations. The plan for this table is to store the names of applicable airports; then there would be a way to possibly compare the airports in this table to other entries that have the airport abbreviation. Lastly, the Flight_Routes table is a junction table that will be used to add data from the Airports and Flights tables. The only primary key here is the flightroute_id to identify routes based on their index. There could be changes in the future to how these tables are set up as I learn more about relational algebra and databases. There is a basic understanding of where to use primary keys and where foreign keys fall into these tables, but when the time comes to actually compute the information between each table, changes will be made to implement the best practices for this flight booking database.
